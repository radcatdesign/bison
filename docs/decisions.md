# Decisions

Two lists. The first is what I decided while building Phase 0 that the brief didn't specify. The second is what I need from you, each with a recommendation.

## Decided while building (tell me if any of these are wrong)

1. **Next.js 16 with Cache Components on.** It's the current default. Every session read sits behind a `<Suspense>` boundary, so the black frame and nav paint first and data streams in. Middleware is now `src/proxy.ts` (Next 16 renamed it).
2. **Kysely and hand-written SQL migrations instead of an ORM.** RLS policies are the most important code in the app, so they live in plain SQL where they're easy to read and review. Kysely gives typed queries without hiding the SQL.
3. **RLS enabled, not forced, with two roles.** Migrations run as the owner role; the app runs as `bisonops_app`, which can't bypass RLS, belongs to no role and owns nothing. Forcing RLS on the owner would break the small lookup functions webhooks need. A test fails the build if the app role ever gains bypass powers or a table ships without the policy.
4. **Roles live in Bison Ops, not in Clerk.** Clerk handles sign-in and organization membership. Owner, Admin, Sales, Marketing and Viewer are stored in `members`. This avoids Clerk custom-role setup per environment and keeps roles working if the auth provider ever changes.
5. **Stand-ins so the whole thing runs without accounts.** A dev sign-in (four made-up people at two made-up companies) replaces Clerk locally and in tests, and is refused on Vercel production. A test billing provider turns items on without Stripe. Real Clerk and Stripe switch on with env vars.
6. **Trials are app-side.** Stripe trials apply to a whole subscription, not one item, so a 14-day trial of one module is an entitlement row with an end date. No card needed. One trial per item per tenant.
7. **Shared contact pages are in Sales and also sold alone.** The brief lists contact sharing under Sales and as an add-on. Both grant the same feature.
8. **Sample data is on for new tenants, generated, never stored.** It's built from a seeded random generator keyed to the tenant, so it's stable and different for every company. Writes refuse while it's on.
9. **Events are partitioned by month.** A daily cron keeps partitions two months ahead and drops data past each tenant's retention (`/api/cron/daily`, scheduled in `vercel.json`).
10. **Webhooks are deduped in the same transaction as the work,** so a failed run can be retried by Stripe without double-processing.
11. **Plain CSS with tokens, no Tailwind.** Brand values are custom properties in `src/app/tokens.css`, so white-label is a token swap. The look is modern and light by default, with a full dark theme that follows the device or a per-person choice (Match my device, Light, Dark) saved in the browser and applied before the page paints. Fonts are Mona Sans (text and numbers, with tabular figures) and Geist Mono (paths and keys), self-hosted from npm. Icons are Lucide.
12. **Last mode is remembered in a cookie set by the browser,** not by the server, so link prefetching can't change it.
13. **Marketing and Sales show a short "being built" overview** when unlocked, until Phases 2 and 3 replace it.
14. **Postgres 16** locally and in tests. Neon runs 16 and 17; nothing here depends on 17.
15. **Domains are unique only once verified.** Anyone can add a domain to their account, but only one account can verify it (DNS check, Phase 1). Nobody can lock a competitor out, and the app never says which domains belong to customers.
16. **New Clerk members wait for approval.** Only invites made in Bison Ops activate on their own. Everyone else is `pending` until an owner or admin approves them (the approve button ships with team management in Phase 1).
17. **Billing and dev sign-in fail closed.** Test billing and the dev sign-in refuse to run on Vercel production, and need an explicit flag in any other production build.
18. **An independent security review** of tenancy, auth and billing ran before this was pushed. Every finding was fixed and has a test.
19. **A public demo mode.** `DEMO_MODE=1` with no `DATABASE_URL` runs the portal with the made-up companies and people, sample data, and every save refused (see 21 for turning modules on). It needs no database, Clerk or Stripe, so a Vercel deploy shows the product in a minute. It refuses to turn on if a database is configured.
21. **In the demo, owners can unlock modules and add-ons.** Starting a trial or subscribing works the way it will for real, so people can see a locked mode open up. What they turn on is kept in a cookie in their own browser for 30 days, checked against the catalog and the two demo companies on every request, and never reaches a server. Each visitor starts from the same place, and "Reset the demo plan" on the item's page puts their company back. Everything else in the demo still saves nothing.
22. **Pages live in Marketing.** The landing page maker is part of the Marketing module (feature `marketing.pages`), not the AI Assistant, because a landing page is marketing work and the agent is how you use the tool, not a separate product. Owners, admins and the Marketing role can build and publish.
23. **The agent edits through tools, never by rewriting the page.** Claude gets six tools (add, update, remove and move a section, set the style, set search details), and each call is checked against the page schema and applied as soon as it streams in. The preview fills in while it works, a bad call can't break the page, and every change can be undone.
24. **The agent never invents facts.** No made-up quotes, reviews, prices, dates or numbers. It writes yellow `[Add ...]` placeholders instead, and a page can't be published until they're filled in. Copy follows the Bison Ops rules: plain, no em dashes (stripped if one slips through), no buzzwords.
25. **Claude Sonnet 5.5 by default,** set with `ANTHROPIC_MODEL`. It's fast enough to watch and good at plain copy. The Anthropic SDK is pinned to 0.132.1; the 1.x line shipped a day ago with a breaking API change, so it waits until it's had time in the wild.
26. **An offline helper when Claude isn't connected.** Tests, local work and the demo (until a key is set) use a rules-based stand-in that builds from a brief and follows short, direct changes. It says plainly that it's the offline helper.
27. **Pages ignore sample mode.** They're content a company makes, not data it measures, so they save with sample data on or off.
28. **Published pages live at `/p/<company>/<page>` on the Bison Ops domain for now.** Drafts are never public. The tenant's own domain comes later (see below).
29. **Page forms send to Contacts** as a contact plus a submission marked `landing-page`. A filled hidden field or a send under 1.5 seconds is kept as spam with no contact.
30. **In the demo, pages stay in the visitor's browser,** starting with one finished example page per company. Publishing explains that pages can't go live in the demo.
32. **The Bison logo is the product mark.** One shape, drawn in the current text color so it follows light and dark mode: on a dark tile in the sidebar and app icons, on its own on the sign-in screen. The original files are in `public/brand/`. The old "B" mark and its accent dot are gone.
33. **The page editor's preview runs no scripts.** It first loaded an app page inside a sandboxed frame, which never started on Vercel. Now the editor renders the page into a blank, script-free frame, which is faster and has nothing to break.
34. **Eight page templates, not dozens.** Quote request, product launch, seasonal sale, consultation, event, trade program, free guide and simple contact cover what small businesses build most, each in a different look so the choice is easy. Cards show each template in its own colors; using one applies the company's brand color unless they untick it. Copy works for most businesses as written, and anything only the business knows is a yellow placeholder, the same rule as the agent.
31. **A second security review of Pages ran after the first push.** Nothing let one company reach another's pages and there was no script injection. It found six smaller issues, all fixed with tests: agent requests now count in their own table when they start, under a per-tenant lock, and can't be erased; published pages go offline when Marketing lapses, and pages can always be taken down; public forms use a server-signed timing token, rate limits, a size cap on read, and never overwrite a known contact's name or phone; the preview frame is sandboxed by header and checks who's talking to it; nothing can be framed by another site; and the demo limiter reads the platform's address header with a daily ceiling.
20. **Landing page previews load the real page in a sandboxed frame.** It's live and free, and it's what heatmaps will paint over. Some sites block framing; for those, scheduled screenshots (Phase 1) fill in. Sample mode previews made-up sample sites instead of whatever lives at the sample domain.
